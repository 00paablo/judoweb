# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Stack

static HTML/CSS/JavaScript; existing codebase

## Users

Inferred from the existing pages and request: Spanish-speaking Judo learners, clubs, instructors, and friends organizing informal competitions.

## Product Purpose

The site explains Judo through its philosophy, techniques, belts, history, and vocabulary, and gives a group a simple way to create and run a custom tournament on a shared scoreboard.

## Positioning

It combines a practical Judo learning reference with a lightweight, no-account tournament desk for dojo sessions.

## Operating Context

Visitors browse the educational pages on desktop or mobile; groups use the Tatami flow during practice to enter participants, create a bracket, and run matches with the scoreboard.

## Capabilities and Constraints

The site is a multi-page static experience. The educational routes cover philosophy, techniques, belt progression, history, and glossary; the Tokui-Waza explorer lives inside the Techniques route rather than as a standalone page. The tournament builder supports participant entry with weight, a readable single-elimination bracket, byes, and a match scoreboard with a start bell. The scoreboard page also includes a local Professor Kano assistant for common Judo questions. No external account or Google sign-in is required.

## Brand Commitments

The product name is Judo (柔道). Existing Judo terminology, Spanish language, Japanese terms, and the Tatami concept remain recognizable. The user requested a more professional visual presentation.

## Evidence on Hand

Existing source pages and interactions in the project root: index, filosofía, técnicas, cinturones, marcador, historia, and glosario. No external testimonials, customer claims, or brand asset pack is present.

## Product Principles

- Make the Judo content easy to understand and return to.
- Make tournament setup fast enough for a live dojo session.
- Use clear, credible language instead of decorative filler.
- Keep routes, terminology, and interactions consistent across the site.

## Accessibility & Inclusion

The site should remain keyboard usable, readable on small screens, and understandable without relying on color alone.
